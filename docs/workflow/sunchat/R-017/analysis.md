## A-1 前段无效信息稀释步频(已确认)
问题:真人两次实测 cadence=48.6/54.4(物理不可能),数值域与死段时长负相关。
- [CODE] backend/core/pose.py:238 — `span = ts_a[det[-1]] - ts_a[det[0]]`;
  cadence = IC计数 ÷ 检出人物质心的总跨度(非跑动段时长)
- [CODE] pose.py analyze_video — det = "检出人体即入列",站立/走位/掏手机帧 conf 高
  → span 被无效段拉长,IC 计数不变 → 步频被稀释
- [RUN] 合成实验(会话 2026-09-13):纯跑3s cad=142 → 前3s站立+跑3s cad=80.7 →
  前6s站立+跑4s cad=66.3;cycles 几乎不变、span 翻倍,稀释机制实锤
- 结论 C-A1:现有抽帧与"内容是否有效"完全无关;真实手持拍摄必然含入画/走动/拿手机
  段,该缺陷稳定复现,与竖直法好坏正交。

## A-2 帧率元数据不可信,真实帧率只能逐帧 PTS 实测(已确认)
问题:变更需"检测真实帧率",先验证元数据可用性。
- [RUN] 合成 120帧/标称240fps/PTS拉长8×(模拟 iPhone 慢动作容器语义):
  `avg_rate=28800/953≈30.2` 与元数据打架;PyAV 无 container.time_base
- [RUN] 请求20fps采样:源30fps成片取40帧@19.8fps(正常);源真60fps 同样只取40帧
  (上限20fps 生效)——采样按**显示时间轴**,慢动作时间被拉长→等效常速过采 N 倍,
  但 cadence=事件/显示秒 → 慢动作素材测得步频=真实值÷N(48.6 若源自慢动作也是这条通道)
- 结论 C-A2:必须 demux 全量 packet PTS → 中位间隔倒数 = 实测显示帧率 f_eff;
  标称fps(NOMINAL,如 iPhone 慢动作 240)与 f_eff 之比 ∈{2,4,8} 即慢动作倍速 N,
  cadence 还原 = cad×N(VFR 抖动>0.35 标记降级)。

- [CODE] 全仓无旋转处理:`grep -rn "rotate|rotation|displaymatrix|display_matrix|EXIF|

- [RUN] 真实素材反证(本机既有落盘帧,2026-09-13 真人侧跑实拍同一视频,本地 mediapipe 量):

  机制(标注为推断,元数据本身未从原始视频直接读出——原视频未落盘):①若源带显示旋转
