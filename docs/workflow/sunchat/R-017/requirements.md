## 背景
用户想分析跑步姿态。现状 R-010 仅均匀抽 4 帧喂 VLM:跑步一个步态周期约 0.7~1s,
姿态关键信息(着地瞬间膝角、骨盆侧倾、蹬伸角度)发生在毫秒级"反转点",4 帧随机
落点大概率错过,VLM 也无法从像素可靠地"量角度"。需要引入姿态估计关键点路线:
逐帧 33 关节点(信息密度远高于 N 帧图)+ 可计算的量化指标 + 少量骨架标注帧 +
VLM 生成教练式解读报告。[REQ 用户会话 2026-09-13 + CODE core/video.py:52 均匀采样实况]

## 与历史需求的关系
- 继承 R-008:帧与骨架标注图仍以 chat image 形式落盘、走 /chat/images/{id} 回显。
- 修改 R-010:`/chat/video/frames` 保持原 behavior 不变(默认 4 帧均匀),新增
  独立端点做姿态分析,不动旧接口签名,桌面/移动视频输入零回归。
- 继承 R-013:新环节按 `evt=pose.* result=ok|fail` 留痕。
- 继承 R-014:移动端 /m 提供发起入口(同视频按钮旁)。

## 目标用户
个人用户(单用户本地模式),用手机侧拍自己跑步的短视频,获得姿态量化报告与改进建议。

## 核心场景
- S1:用户在 /m(或桌面 ChatView)点"跑步分析"→拍/选一段跑步视频(侧拍 3~10s)
  →页面显示"分析中"(预计 10~30s)→返回报告消息:量化指标表 + 骨架标注代表帧 +
  改进建议文字。
- S2:视频不合格(非侧拍/人太小/抖动/无完整步态周期)→明确拒析文案,提示重拍要点,
  不输出误导性数字。
- S3:服务器未装视觉模型时→仍输出数值指标 + 固定模板报告(降级不报错)。

## 边界与非目标
- 明确包含:路跑"跑过相机前方"侧拍与跑步机固定侧拍两类场景;单用户;结果仅以对话
  消息呈现(指标 JSON 随消息元数据存储,不建独立记录表);报告端 VL+降级双路。
- 明确不做(非目标):实时直播流分析;3D 动作捕捉;力量/训练计划生成;多人体视频
  (只分析画面中置信度最高者);历史分析记录管理页(二期);跑步机/原地场景特化。
