# R-018 决策记录

需求: R-018 | 日期: 2026-09-26

## D-1 朝向角度在像素域计算(r1.1 澄清,非语义变更)
- 背景: `detect_orientation(lms, frame_hw)` 接口里 `frame_hw` 在 r1 未写明用途。
- 决策: 归一化关键点求 u 向量前,先按 `x*W, y*H` 还原像素坐标再单位化/算 θ。
- 理由: 归一化坐标下 (0.5, 0.1) 的"竖直"在 480×640 与 640×480 里角度不同;
  像素域才算得出真实画面倾角。A-5 实测(113~134px 的肩髋距、θ=-87~-95°)本身就是像素域测量。
- 影响: 无接口变更;写进 step-1 单测(AC-4 用两种 `frame_hw` 喂同一内容,断言 θ 随之变)。

## D-2 undetermined 与 orient="0" 走完全相同代码路径
- 用户确认(架构门禁补充口径): 不可定时不转、指标照常输出、**不新增拒析理由**,
  只在 quality/报告/日志体现。避免与既有三重门槛叠加成更多误拒(FR-6)。

## D-3 转正落点唯一在采样侧(P1)+ 取帧侧(P4),P2 skeleton 零改动
- 理由: 朝向归一化若在多处各转一半,会出现"指标转正、骨架仍横躺"的新裂痕;
  P2 通过 AC-5 负例单测钉住"同 k"契约,而不是自己再判一次。

## D-4 skeleton/报告不读元数据、不做四向试探(A-4 硬约束)
- 四向试探"取可检出者"在真人素材上必选错(真 upright 在生产门槛 0.5 检不出),
  故 FR-2 把"能否检出"列入禁用判据,AC-4 以 grep + 变体断言双向钉死。

## D-5 rot 档位命名与方向约定(rot_k = q/90,q=人体顺时针偏转角)
- `np.rot90` 为**逆**时针;k=1 把画面左缘转到下缘。
- 判定 θ=atan2(u_x, −u_y)(0=头朝上,顺时针为正),q=round(θ/90)*90,修正档 `rot_k=q/90`。
- 对外档位串描述**原始画面里人体的偏转方向**:`"0"` 正立、`"90cw"` 头朝右、
  `"180"` 头朝下、`"270cw"` 头朝左;报告文案"画面已按人体朝向转正(原为 270cw)"按源朝向读。
- 已实测钉死(4 档 × 真值 `(4−src_k)%4` 全对,夹具与 np.rot90 逐像素同构)。

## D-6 `_pace` 腿长像素距口径**不改**(v1 疑似缺陷经核实为等价写法)
- `math.dist((x, y*H/W))·W` 与 `math.dist((x*W, y*H))` 恒等(先乘后乘同系数),
  v2 代码本就是一个正确像素距的紧凑写法,转正/横躺两种帧序下均正确,无需改动。
  AC-2(正立逐值不变)+ 本次 AC-1(横躺转正 cad ±5%)双向锁定。

## D-7 `orient_samples`/`orient_conf` 全分支如实回显(r1.1,实现时澄清)
- r1 接口节"未定=0.0"表述只适用于全弃权/样本不足;实现让 `orient_samples` 在所有分支
  如实计数、低一致度 undetermined 也回显真实占比(0.5 这类值对排障关键)。
  判定语义不变,仅诊断字段更诚实;单测 `test_undetermined_few_samples`/
  `test_low_agreement_undetermined` 钉住。
