# R-018 需求:跑姿分析抽帧朝向归一化(以人体头脚轴为基准)

需求: R-018 | 类型: bugfix(影响>2 文件+接口键变更 → 标准流程) | 日期: 2026-09-26
基线: design/overview.md + R-017(design/ 回写前以 R-017/design-change.md 为准)
上游: R-017/A-5、R-017/state.risks[R-11](occurred) | 取证: R-018/analysis.md A-1~A-6

## 背景与现象
用户手机上传跑步视频后,R-017 报告出现物理不可能的数值(cad 54.4 / 48.6,骨盆侧倾
-42.1°/-31.9°/-28.4°),且历史报告自身反复声明"4帧画面整体旋转90°、骨架线交叉漂移"。
[RUN] 已定位第二失效通道(独立于 R-017/A-1 稀释,后者已修):抽帧**不应用显示旋转元数据**
(PyAV `to_image()` 给码流原像素),而手机端素材进系统时人体在帧内是**横躺**的
(实测肩中点→髋中点偏离竖直 89.8°~92.9°,bbox 高/宽 0.28)。v2 整条指标链以竖直 y 轴
为前提(踝 y 振荡 / 髋 y 自相关 / y>μ+kσ 切 IC-TO / 像素 x 距算配速),等于**量错轴**:
踝真振荡轴由 y 变 x、body_ratio 0.306→0.152(逼近 0.12 误拒线)、pelvic_tilt +1.0°→+91.4°。

## 用户明确指令(本需求验收基准)
> "横屏竖屏不能作为旋转依据。要识别人的朝向。以人头上脚下为基准来控制旋转。"

即:**不得**以画面宽高比、**不得**以容器 rotate 元数据作为旋转依据;必须以**检出人体自身
的头脚轴**判定并转到"头朝上、脚朝下"。原因:手机可能横拍/竖拍/带或不带元数据,
而算法真正需要的是"人在画面里正立"。

## 功能需求
| ID | 需求 | 依据 |
|---|---|---|
| FR-1 | 朝向判定以**人体自身几何**为唯一依据:`u=单位化(肩中点−髋中点)`,180°歧义用"鼻在 u 上的符号"消解;量化到最近 90° 档;偏角落在量化边界带(距档心 >15°)时判"不可定",不转 | A-5(实测 4 帧 -87°~-95° 一致,裕度充足) |
| FR-2 | **禁止**用画面宽高比、容器/stream rotate 元数据、"某朝向能否检出 MediaPipe"作为判定依据或优选条件 | A-4(真 upright 在生产门槛 0.5 下检不出,降 0.15 才出且 vis 0.70;"能检出"非可靠信号) |
| FR-3 | 判定在**原图一次检出**的关键点上完成(粗扫帧),多帧**投票**取多数,记录一致度;不得为判朝向而做四向重复推理(性能与 A-4 双重不可靠) | A-4/A-5 |
| FR-4 | 判定生效后,该请求的**密采帧与骨架帧绘制轴**必须与判定所用坐标系一致(同一 k 值应用于解码帧),保证指标/骨架/裁剪三者同源 | 防"指标转正、骨架仍横躺"的新裂痕 |
| FR-5 | 透明度:quality 增 `orient`(如 `"0"/"90cw"/"180"/"270cw"/"undetermined"`)、`orient_conf`(投票一致度,0~1);报告透明度行打印"画面已按人体朝向转正(头朝上)"或"朝向不可定,指标可能失真";evt 日志 fields 增 orient | R-017 FR-8~12 透明度约定同族 |
| FR-6 | 不可定时**不转**,且不得静默:除 FR-5 透明度声明外,该请求指标仍照常输出(不新增拒析理由),由报告文字提示可信度降级 | 避免与 R-3 门槛叠加成"更多误拒" |
| FR-7 | 转正后既有质量门槛(FR-3 三重门槛的 body_ratio 等)取值恢复真实人体尺度,body_ratio 不因横躺被压低而误拒 | A-3(0.152→0.306) |

## 验收标准(AC)
| ID | 标准 | 验证方式 |
|---|---|---|
| AC-1 | 给定"人横躺 90°"夹具(sample_frames 注入面产出横向躯干帧),`orient` 判为对应 90°档,转正后 `_metrics` 的 cadence 回到已知真值 ±5% | 单测:test_pose_core(合成横躺夹具) |
| AC-2 | 给定已正立夹具,`orient="0"` 且指标与不转正时**逐值相同**(不误转、不引入偏差) | 单测 |
| AC-3 | 无人体/关键点缺失/一致度<阈值/偏角落边界带 → `orient="undetermined"`,不转、不新增拒析、透明度行含降级文案 | 单测×3 分支 |
| AC-4 | 判定**不读**元数据与画面宽高比:同一内容分别伪装"带 rotate=90 元数据"与"不带"、"竖幅"与"横幅",判定结果只随**人体朝向**变化 | 单测(夹具旋转 vs 元数据解耦断言) |
| AC-5 | 骨架帧与裁剪帧与转正后坐标一致(骨架不横躺、crop_bbox 在转正系内) | 单测(AC-10 同族断言扩展) |
| AC-6 | 真人真机活体:手机实拍侧跑(横屏录 + 竖屏录各一段)→ cad∈[140,220],报告打印朝向透明度行,骨架帧人正立 | step-8 实拍对账(真实视频豁免单测) |
| AC-7 | 全量 pytest 零回归(基线 340 passed 1 skipped),既有用例不因 quality 增键而失败 | 全量测试 |
