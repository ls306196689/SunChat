## 一、判向(真实 MediaPipe,256px 粗扫)

| 内容 | 检出 | mean conf | orient | rot_k | 投票 conf | 样本 | abstain |
|---|---|---|---|---|---|---|---|
| 正立 | 8/8 | 0.76 | `0` | 0 | 1.0 | 8 | 0 |
| **倒立 k=2** | **8/8** | 0.76 | **`180`** | **2** | **1.0** | 8 | 0 |

逐帧 θ(=atan2(u_x, −u_y),归一化→像素域):
`-173.4 / -172.9 / -175.1 / -174.2 / -170.5 / -174.0 / -171.1 / -171.9`
→ 每帧 `q=round(θ/90)*90=180`,偏差 4.9°~9.5° **全部 < `POSE_ORIENT_EDGE_DEG`=15**,
无弃权。**180° 消歧靠的是鼻在 u 上的符号**:`u=肩中点−髋中点` 在倒立时指向图像下方,
θ 落在 ±180 附近而非 0,与正立天然分开(不是靠"哪档检得出",那是 A-4 明令禁止的判据)。

检出率没有因倒立而崩塌(8/8、100/100)——这一点值得记下来:
`pose_landmarker_lite` 对上下颠倒的人体**照样给出关键点**,所以"能检出"绝不能当判向依据
(正是 A-4 的结论,这里再多一例反证)。

## 二、只转一刀的隔离(全分辨率,width=0,同编码世代)

方法逐字沿用 step-4c §三:`sample_frames`→`_detect_landmarks`→`detect_orientation`
→(k≠0 则转正+重跑粗扫)→`locate_activity`→密采同 k→`_metrics`,**不套终门**。

| 组 | orient | rot_k | 检出 | body_ratio | segs | cycles |
|---|---|---|---|---|---|---|
| A 正立基准 | 0 | 0 | 20/20 | **0.475** | [] (短样本) | 0 |
| B 倒立+按判定转正 | **180** | **2** | 20/20 | **0.476** | [1.2,2.0] | 1 |
| C 倒立+不转正(v2 旧行为) | 180 | 0(不转) | 20/20 | **0.479** | [] | 0 |

**与 90° 的关键差别(诚实记录)**:90° 横躺会把 body_ratio 从 0.476 打到 0.316、
打掉竖直法 → 门槛误伤(step-4c);而 **180° 保持竖直范围**,body_ratio 三组几乎相同
(0.475/0.476/0.479),**门槛不会被 180° 误伤**。所以 180° 的危害不在"检不出/被拒",
而在下一节的"读数全部错位"。

## 三、180° 不转正到底坏在哪(强制整段,同字节同时间窗)

`locate_activity` 在这段 4s 合成素材上给出的段不稳定(A/C 为空、B 只有一段),
直接比 metrics 会被"段有无"混淆。故第三探针**绕过段定位**,把整条 4s 当作一组,
B 用 `rot=2`、C 用 `rot=0`,其余全同(检出均 100/100):

| 指标 | B 转正 rot=2 | C 不转 rot=0 | |
|---|---|---|---|
| pelvic_tilt_deg | **+2.6** | **−20.4** | 骨盆倾角被读成"反向 20°" |
| asymmetry_pct | **25.3** | **59.9** | 左右不对称虚高一倍多 |
| stance_swing_ratio | **0.935** | **0.534** | 支撑/摆动比失真 |
| knee_angle_at_contact_deg | 173.4 | 164.2 | 触地膝角偏 9° |
| knee_angle_at_toeoff_deg | 167.0 | 172.6 | 离地膝角偏 6°(且与触地关系倒置) |
| hip_rom_deg | 45.4 | 47.9 | 髋活动度偏 2.5° |
| cadence_spm | 353.9 | 320.2 | 数值本身仍不可用(T-3),只作"同批不同读数"的旁证 |

**左右标签镜像的机械证据**:六个关键点满足 `x ≈ 1 − x_other`
(L_wrist 0.547 ↔ R_wrist 0.449、L_ankle 0.531 ↔ R_ankle 0.469、L_shoulder 0.498 ↔ 0.44…)
→ 不转正时图像上下+左右同时翻转,MediaPipe 在新位置上重新分配 L/R,
**报告里"左腿/右腿"的归因会指向错的腿**。这正是 `asymmetry_pct` 从 25.3% 蹦到 59.9% 的机制,
与线上 R-017 观察到的"asym 异常大"现象同源。

结论:180° 档的真实收益 = **骨盆倾角/支撑摆动比/左右不对称等带方向与带标签的量回到正确坐标系**;
它不改善检出率,也不影响门槛(FR-7 的"不误拒"在 180° 上本就成立)。
`rot_k=2` 走的是与 `k=3` 同一条 `np.rot90` 通路,端点取帧同 k(FR-4)在 step-4c §六已活体验证。

## 四、四档齐全性实测(同一素材,只改源朝向)

`/tmp/r018_foukdir.py`:正立素材经 `np.rot90(k=0/1/2/3)` 造四份(同一编码世代、同 256px 粗扫),
判向结果与"源朝向"真值逐一相符 → 四档在真实推理下**全部覆盖**,不再靠同函数类推:

| 源(rot90 k) | 期望 orient/k | 实得 | 检出 | 投票 conf |
|---|---|---|---|---|
| k=0 正立空转 | `0` / 0 | `0` / 0 ✓ | 8/8 | 1.0 |
| k=1 | `270cw` / 3 | `270cw` / 3 ✓ | 8/8 | 1.0 |

若当初把二者写反,这张表就会 FAIL,可作为回归时的方向性真值表。
