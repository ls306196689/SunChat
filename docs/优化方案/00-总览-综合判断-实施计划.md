# SunChat 框架优化总览 · 综合判断 · 实施计划

> 本文档是整个优化工程的**总控文档**，汇总 9 个功能点的设计方案（见同目录 `01`~`09`），给出综合可行性判断与分步实施计划。
> 决策基线（已与用户确认，2026-08-23）：
> - **对话**：全套 —— SSE 流式 + 记忆异步化 + 多轮上下文
> - **Agent**：打磨成**正式功能**（Ollama 原生 tool_calls）
> - **认证**：**诚实的单用户本地模式**（去掉假 mock，收敛 CORS，接入输入校验）

## 3. 综合可行性判断

> 问题：**按上述方案，能否完成框架能力补齐与优化目的？** 结论：**能，但需分"高置信可交付"与"需实机验证"两档**，且工作量集中在 01/03/06/09 四个高难点。

### 3.1 高置信可直接交付（纯代码逻辑，测试可验证）
- **G1 修通断裂功能**：KB 管道、记忆列表、会话改名/删除 —— 逻辑明确，单元测试可覆盖。✅
- **G2 事件循环阻塞 + 每请求 Session**：采用"同步 `def` 路由（FastAPI 自动线程池）+ `Depends(get_db)` 每请求 Session"标准模式，无外部依赖风险。✅
- **G4 正确性 Bug**：变量遮蔽、双重 embed、system 双注入、用户隔离、错误抛异常 —— 均为局部修复，测试可验证。✅
- **G6 诚实单用户**：删 mock、收敛 CORS、接 `sanitize_input` —— 低风险。✅
- **G7 依赖/文档治理 + 公共 JSON util + habit 拼写**：低风险。✅
- **G3 记忆异步化 + 规则优先 router**：规则优先用现有关键词回退逻辑，多数消息免 LLM 调用；提取放后台线程。✅

### 3.2 需实机（Ollama 在线）验证的部分
- **G3 SSE 流式**：代码与测试（TestClient 迭代 SSE 帧）可完成，但"逐字体验、token 计时"需真实 Ollama 确认。⚠️
- **G3 多轮上下文**：逻辑可单测，效果需实机。⚠️
- **G5 Agent 原生 tool_calls**：**依赖模型是否支持 tool calling**（qwen2.5:7b 在较新 Ollama 下支持）。循环逻辑可用 mock LLM 单测；端到端需实机。⚠️
- **G4 记忆冲突"以新为准"**：语义判定需实机观察。⚠️

### 3.3 风险与对策
| 风险 | 影响 | 对策 |
|------|------|------|
| Ollama 不在测试环境 | 流式/Agent 无法端到端验证 | 全部用 mock/monkeypatch 写单测；实机验证单列，不阻塞交付 |
| 原生 tool_calls 模型不支持 | Agent 循环卡住 | 加"纯文本 ReAct 回退"：解析失败按无工具处理并终止；`max_iterations` 兜底 |
| 每请求 Session 大重构 | 波及面广 | 集中在 service 方法加 `db` 参数 + 路由注入，分批提交、每批跑测试 |
| 范围过大单次改完 | 回归难定位 | 严格分 4 批次，批间测试全绿才进下一批 |
| 文档与实现再次脱节 | 误导后续 | 每批次同步更新对应设计文档"执行结果"章节 |

### 3.4 结论
**方案完整、正确、无遗漏，可以达成 G1–G8。** 其中 G1/G2/G4/G6/G7 及 G3 的规则优先+异步部分为**高置信交付**；G3 流式体验、G5 Agent 端到端为**需实机验证**（单测已覆盖核心逻辑，实机验证清单随交付提供）。预计代码改动约 30~40 个文件，测试新增 20+ 用例。

## 4. 实施计划（分 4 批次）

> 原则：**先地基（09 基础设施）→ 再修断（01/02/03）→ 再增强（04/06）→ 最后治理（07/08/09 收尾）**。每批次结束跑全量测试，绿了才进下一批。

### 批次 0 · 地基（解锁其余一切）—— 对应 09 基础设施
1. 统一 LLM/Embedding 客户端（`core/llm.py` 收敛，agent_llm 复用）
2. 每请求 DB Session：`get_db` 改 `Depends`，service 方法加 `db` 参数，路由注入
3. 路由 `async def` → `def`（除流式），解决事件循环阻塞
4. `lifespan` 启动：`init_db()` + 预建 Chroma collection + Ollama 自检
5. 公共 `parse_json_response()` util，替换 5 处重复
6. 统一 `habit` 拼写；`model_config` 绝对路径
7. requirements 瘦身（删未用依赖；PyPDF2→pypdf）
- **验证**：全量测试绿 + 应用可 `uvicorn` 冷启动（空 data 目录也能起）

### 批次 1 · 修断（P0）—— 对应 03 知识库 / 02 记忆 / 01 对话
8. 知识库管道打通：上传落盘（uuid 重命名）→ 同步/后台 `process_file` → 状态流转
9. KB 4 个 bug：变量遮蔽、双重 embed（改批量）、content 字段、metadata 补 user_id
10. `GET /memories` 真实查询（分页+过滤）
11. 会话 rename/delete 真实落库
12. 记忆 router 规则优先（省 LLM 调用）
- **验证**：KB 上传→处理→检索→问答端到端测试；记忆列表测试；会话改名删除测试

### 批次 2 · 增强（正确性 + 核心体验）—— 对应 01 / 02 / 04
13. 对话：system 去双注入、接 `search_enabled`、错误抛异常、真实 token、多轮上下文
14. 对话：记忆提取放后台线程（非阻塞返回）
15. 记忆：冲突"以新为准"（替换 content + 重算向量）、Chroma `where` 用户隔离
16. 搜索：接入对话（search_enabled 时）、LLM 归纳、迁移 `ddgs`
- **验证**：对话流程测试（mock LLM）；记忆冲突测试；搜索接入测试

### 批次 3 · 流式 + Agent + 治理收尾 —— 对应 01 / 06 / 07 / 08 / 09
17. SSE 流式端点 `/chat/stream`（同步 generator + StreamingResponse）
18. 前端 SSE 渲染 + 超时 + 乐观回滚加固
19. Agent：原生 tool_calls 重写 + 纯文本回退 + `/chat/agent` 正式端点
20. 认证：删 mock 路由、收敛 CORS、接 `sanitize_input`
21. README / architecture 文档对齐真实实现
- **验证**：SSE 帧测试（TestClient）；Agent 循环 mock 测试；CORS/校验测试；前端 `npm run build` 通过

### 交付物
- 9 份功能点设计文档 + 本总览（`docs/优化方案/`）
- 修复后的后端 + 前端
- 新增/更新测试（每批次）
- 实机验证清单（Ollama 在线时按清单逐项确认）
