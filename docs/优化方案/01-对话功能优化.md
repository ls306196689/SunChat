## 1. 现状
- 路由：[chat.py](../../backend/app/api/v1/routes/chat.py) — `POST /chat/messages`（非流式）、会话 CRUD。
- 服务：[chat_service.py](../../backend/services/chat_service.py) — `process_message`（单条消息全流程）、`process_message_stream`（未接线）。

## 3. 优化设计

### 3.1 整体流程（优化后）
```
POST /chat/messages          POST /chat/stream
      │                            │
      ├─ sanitize_input           ├─ sanitize_input
      ├─ router(规则优先,快)       ├─ router(规则优先,快)
      ├─ 记忆检索(embed+Chroma)    ├─ 记忆检索
      ├─ 取最近 N 条历史           ├─ 取最近 N 条历史
      ├─ 拼 prompt(system 单份)    ├─ 拼 prompt(system 单份)
      ├─ LLM 生成(非流式)          ├─ 返回 SSE，LLM 流式生成(首字快)
      ├─ 落库 user+assistant       │     (逐块 yield)
      └─ 后台线程: 记忆提取+落库   └─ 流结束: 落库 + 后台记忆提取
```

### 3.2 关键决策
- **router 规则优先**：先用 [memory_router._fallback_analysis](../../backend/core/memory_router.py#L176) 的关键词规则判断；仅当规则未命中（`needs_memory_query` 不确定）时才调 LLM。多数消息省掉 router 的 LLM 调用，这是流式首字快的前提。
- **system 单份注入**：`generate(prompt, system)` 只把 system 作为 system 消息，user prompt 只含 `用户: {content}` + 历史，不再拼 system。
- **错误不吞**：`ollama_service.generate` 失败**抛异常**（新增 `raise_on_error=True` 默认），路由捕获返回 503；非流式路径不再产生空 assistant 消息。
- **记忆提取异步**：非流式用 `BackgroundTasks`；流式在 generator 结束后启动后台线程。提取失败只记日志，不影响主响应。
- **多轮上下文**：`get_recent_messages(session_id, n=6)` 取最近 N 条（user/assistant 交替）拼进 prompt。
- **真实 token**：从 Ollama 响应 `eval_count`/`prompt_eval_count` 取，写入 `Message.tokens_used`。

### 3.3 SSE 流式端点
```python
@router.post("/chat/stream")          # 注意：def 而非 async def
def stream_chat(req: ChatRequest, db = Depends(get_db)):
    def gen():
        # 前置：router + 记忆检索 + 拼 prompt（同步，线程池内）
        ctx = chat_service.build_context(db, req, history_n=6)
        user_msg = chat_service.save_user_message(db, req)
        for chunk in chat_service.stream_generate(ctx):   # 同步 generator
            yield sse({"type":"delta","content":chunk})
        # 收尾：聚合全文 -> 存 assistant 消息 -> 后台记忆提取
        chat_service.finalize_stream(db, req, full)
        yield sse({"type":"done","done":True})
    return StreamingResponse(gen(), media_type="text/event-stream")
```
- 用**同步 generator + `StreamingResponse`**（Starlette 自动放线程池），无需重写 async httpx 客户端，复用现有 `requests` 流式。
- 前端用 `fetch` + `ReadableStream` 读 SSE（axios 不支持流式，见 08）。

### 3.4 会话 CRUD 落库
- `PATCH /chat/sessions/{id}` → 更新 `ChatSession.title`。
- `DELETE /chat/sessions/{id}` → 软删 `deleted_at = now()`（与 `list_sessions` 的 `deleted_at == None` 过滤一致）。
