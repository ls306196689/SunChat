## 3. 优化设计

### 3.1 `GET /memories` 真实查询（M1）
```python
@router.get("/memories")
def list_memories(type=None, category=None, page=1, page_size=20, db=Depends(get_db)):
    q = db.query(Memory).filter(Memory.user_id == USER_ID, Memory.is_active == True)
    if type: q = q.filter(Memory.type == type)
    if category: q = q.filter(Memory.category == category)
    total = q.count()
    rows = q.order_by(Memory.created_at.desc()).offset((page-1)*page_size).limit(page_size).all()
    return {...}   # 含 id/type/category/content/importance/created_at
```

### 3.2 记忆冲突"以新为准"（M2）
`update_or_create_memory` 重写为：
1. `search_memories(query=content, top_k=3)` 找相似。
2. 命中 `similarity > 0.85`：
   - **更新 content 为新内容**，`updated_at=now`，`confidence += 0.1`（封顶 1.0），importance 取较大者。
   - **重算向量**：`embedding_service.embed(new_content)`，用**新 vector_id** 写入 Chroma（保留 metadata），并 `chroma.delete([旧 vector_id])`；SQLite `vector_id` 指向新的。
   - 返回 `action: "updated"`。
3. 未命中：`create_memory`，返回 `action: "created"`。
> 说明：不用 LLM 判定"是否矛盾"（成本高、不稳定），用高相似 + 内容不同即视为更新，符合"最新为准"。极端矛盾（语义相反但向量相似）属边界，记录日志待后续用 LLM 复核。

### 3.3 用户隔离（M3/M5）
- Chroma `query` 增加 `where={"user_id": user_id}`（metadata 已存 user_id）。
- type/category 过滤改用 Chroma `where` 组合（`$and`），不再 Python 侧滤。
- SQLite 回退路径本就按 user_id 过滤，保留。

### 3.4 router 规则优先（M4）
`analyze_memory_need(user_input)`：
1. 先跑 `_fallback_analysis`（纯关键词规则，无 LLM）。
2. 若规则**明确命中**（`needs_memory_query=True` 且匹配到具体类型，置信度≥0.6）→ 直接返回，不调 LLM。
3. 若规则**未命中或不确定**（含"我/记得/昨天"等弱信号但无具体类型）→ 才调 LLM 精判。
4. `memory_enabled=False` 时**根本不调** router（在 chat_service 层短路）。

### 3.5 其它
- `get_stats.avg_confidence` 改为真实计算：`select(avg(confidence))`（M6）。
- 统一拼写为 `habit`（M7）：router memory_types、extractor category_map、prompt 全部 `habit`；对存量数据加一次 `UPDATE memories SET category='habit' WHERE category='habbit'`（lifespan 迁移）。
- `create_memory` 落库 `extra_data` 增补 `source`/`confidence`（M8）。
