## 3. 优化设计

### 3.1 打通上传管道（K1/K2）
```
POST /kb/upload
  ├─ 读 UploadFile 字节
  ├─ 落盘：data/uploads/{uuid4().hex}_{safe_filename}   # uuid 防碰撞/防注入
  ├─ KBFile 记录：新增 storage_path 列（存落盘绝对路径）、file_type 按扩展名
  └─ 后台线程 process_file(file_id)   # 或同步，见下
```
- **同步 vs 后台**：默认**同步处理**（单用户本地，上传即处理完，状态即时 ready；实现简单、易测试）。大文件可后续切后台线程 + 轮询状态。本次采用同步，接口返回处理结果。
- `process_file(file_id, file_path, file_type)` 复用，`file_path` 来自 `KBFile.storage_path`。
- 状态机：`uploading → processing → ready | failed`（failed 记 `error_message`）。
- `KBFile` 表加 `storage_path = Column(String(500))`（lifespan 里 `ALTER TABLE` 兜底旧库）。

### 3.2 修 4 个正确性 Bug
- **K3 变量遮蔽**：`_search_knowledge_sqlite` 把搜索词参数改名 `keyword`，Query 对象用 `q`，`q.filter(KBChunk.content.like(f"%{keyword}%"))`。
- **K4 双重 embed**：循环内算好的 `embeddings` 列表直接传给 `chroma_client.add(..., embeddings=embeddings)`，不再重算。进一步用**批量嵌入**：`embedding_service.embed_batch(chunk_texts)`（走 Ollama `/api/embed` 复数接口，一次请求全部 chunk），失败再逐条回退。
- **K5 content 字段**：`chroma_client.query` 的 `include=["documents","metadatas","distances"]`，content 取 `documents[i]`（与 memory_service 一致）；去掉 `KBChunk.id == chunk_index` 的错误查询，改按 `metadata.file_id + chunk_index` 关联（或直接用 documents 的 content，不再回查 SQLite）。
- **K6 用户隔离**：Chroma metadata 增加 `user_id`；查询 `where={"user_id": user_id}`（+ 可选 `file_id $in`）。
- **K7 删除落库**：`DELETE /kb/files/{id}` 调 `knowledge_service.delete_file`（已实现，删 Chroma 向量 + KBChunk + KBFile），并 `os.remove(storage_path)` 删物理文件。
- **K8**：`qa` 的 user_id 参数化（路由传 USER_ID）。
- **K9**：`retry_process_file` 用 `kb_file.storage_path`。

### 3.3 批量嵌入（配合 09 统一客户端）
[embedding.py](../../backend/core/embedding.py) 增加 `embed_batch(texts)`，优先 Ollama `/api/embed`（`{"input":[...]}` → `{"embeddings":[...]}`），404/异常时回退逐条 `/api/embeddings`。
