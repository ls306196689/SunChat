# 04 · 搜索功能优化方案

## 1. 现状
- 路由：[search.py](../../backend/app/api/v1/routes/search.py) — `/search`（裸结果）、`/search/history`、`/search/suggest`。
- 服务：[search_service.py](../../backend/services/search_service.py)（封装 + `search_with_introduction` 未用）。
- 核心：[search.py(core)](../../backend/core/search.py) — `DDGS`、`route_query`（正则意图路由）。

## 2. 问题清单
| # | 问题 | 位置 | 严重度 |
|---|------|------|--------|
| S1 | 搜索未接入对话流程，`search_enabled` 开关对聊天无效（同 C3） | chat_service | 高 |
| S2 | `search_with_introduction`（搜索+LLM 归纳+引用来源）写了没人调 | search_service:32 | 中 |

| S6 | 搜索无超时/重试，DDG 可能挂起 | core/search:31 | 低 |

## 3. 优化设计

### 3.1 接入对话（S1）
`chat_service.build_context` 中：当 `search_enabled=True` 时，
1. 调 `search_service.search(query, max_results=5)` 拿结果（带超时）。
2. 用 `search_service._build_context_from_results` 生成摘要文本。
3. 作为**独立段落**拼进 user prompt（"以下是网络搜索结果，可参考：…"），**不**塞进 system，避免与记忆混淆。
4. 结果来源（title/url）可附在 prompt，让 LLM 引用。
> 注意：搜索是外部网络调用，放在前置会拖慢首字。策略：搜索仅在 `search_enabled` 时执行，且加 5s 超时，超时/失败则跳过搜索直接生成（不阻塞主流程）。流式路径下，搜索结果在首字前完成（可接受，用户主动开了搜索）。

### 3.2 LLM 归纳（S2/S3）
- `POST /search` 增加 `summarize: bool = True` 参数：为 True 时调 `search_with_introduction`，返回 `answer` + `sources`；False 时返回裸结果。
- `search_with_introduction` 复用（已有），修掉其内部 `score: 0.8` 硬编码（改为按排名给递减分或去该字段）。

### 3.3 依赖迁移（S4）
- `core/search.py`：`from duckduckgo_search import DDGS` → 优先 `from ddgs import DDGS`，`try/except ImportError` 回退旧包。
- requirements：`duckduckgo-search` 标注 deprecated / 换 `ddgs>=9`（保留回退兼容）。

### 3.4 查询净化（S5）
- `route_query` 不再把记忆拼进 search query（记忆污染搜索词）。记忆只作为 LLM 归纳时的背景（`search_with_introduction` 已支持），搜索 query 保持干净。

### 3.5 超时/重试（S6）
- `DDGS().text(..., timeout=5)`（ddgs 支持 timeout 参数）；失败返回 `[]`（已如此），记 warning。
