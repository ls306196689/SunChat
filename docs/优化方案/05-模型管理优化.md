# 05 · 模型管理优化方案

## 1. 现状
- 路由：[models.py](../../backend/app/api/v1/routes/models.py) — 列表/切聊天/切嵌入/重建向量库。
- 核心：[model_manager.py](../../backend/core/model_manager.py) — 动态解析、TTL 缓存、运行时切换、持久化、向量库一致性。
- **本模块是现有代码里设计最好的部分**，仅需小修。

## 2. 问题清单
| # | 问题 | 位置 | 严重度 |
|---|------|------|--------|
| E1 | `MODEL_CONFIG_PATH = "./data/model_config.json"` 相对路径，依赖 CWD，从别处启动会找不到/写错位置 | config.py:20 | 中 |
| E2 | 启动时不校验 Ollama 可达性，`is_available` 每次同步请求（3s 超时），健康检查可能慢 | health/models | 低 |
| E3 | `set_chat_model` 在 Ollama 不在线时"允许切换（未验证）"，可能切到不存在的模型 | model_manager:201 | 低 |
| E4 | 向量库模型记录 `vector_store_model` 初始为 None（unknown），首启体验不佳 | model_manager:263 | 低 |

## 3. 优化设计
- **E1 绝对路径**：`Settings` 里基于项目根解析。用 `Path(__file__).resolve()` 定位 backend 根，`MODEL_CONFIG_PATH`、`DATABASE_URL`、`CHROMA_PERSIST_DIR`、uploads 目录统一为绝对路径，消除 CWD 依赖。
- **E2 启动自检**：`lifespan` 启动时跑一次 `model_manager.is_available()`，结果存日志 + `/health` 缓存（带 TTL，避免每次 health 都同步探测）。
- **E3 切换校验**：Ollama 不在线时切换仍允许（持久化），但 `/models` 返回里 `available=false` 已能提示；保持现状，文档说明。
- **E4 首启向量库模型**：`rebuild_vector_store` 已 `set_vector_store_model`；首次 `create_memory` 后若 `_vector_store_model is None` 则补记当前嵌入模型（可选增强）。

## 4. 涉及文件
- [config.py](../../backend/app/config.py)：绝对路径
- [model_manager.py](../../backend/core/model_manager.py)：`is_available` 加短 TTL 缓存
- [main.py](../../backend/app/main.py)：lifespan 自检（配合 09）

## 5. 验证
- 单测：
  - `test_config_absolute_paths`：不同 CWD 下 `settings.MODEL_CONFIG_PATH` 指向同一绝对路径
  - `test_is_available_cached`：mock 两次请求 → 实际只打 1 次网络（TTL 内）
- 实机：从任意目录 `uvicorn app.main:app`，模型配置读写正确。
