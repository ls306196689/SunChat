## 3. 优化设计

### 3.1 诚实的单用户模型（U1/U2）
- 定义统一常量 `USER_ID`（本地单用户，值 1），集中到 [config.py](../../backend/app/config.py)（`settings.LOCAL_USER_ID: int = 1`），全项目引用它，消除散落硬编码。
- **删除 mock auth 路由**（register/login/me），在 [main.py](../../backend/app/main.py) 用一个诚实的 `GET /api/v1/whoami` 返回 `{"user_id":1,"mode":"local-single-user"}`，明确"本地单用户、无认证"。
- 文档（README）显式声明：本地优先单用户，无账户体系；多用户为 Roadmap。
> 若日后要多用户，`USER_ID` 常量是唯一切换点（改为从 token 解析），改动面小。

### 3.2 CORS 收敛（U3）
```python
ALLOWED_ORIGINS = [o.strip() for o in settings.CORS_ORIGINS.split(",") if o.strip()]
# 默认 "http://localhost:3000,http://127.0.0.1:3000,http://localhost:5173"
app.add_middleware(CORSMiddleware, allow_origins=ALLOWED_ORIGINS, allow_credentials=True, allow_methods=["*"], allow_headers=["*"])
```
- `CORS_ORIGINS` 进 `.env` 可配。本地前端 dev(5173)/build(3000) 都在白名单。

### 3.3 接入输入校验（U4/U5）
- 在 `POST /chat/messages`、`/chat/stream`、`/chat/agent`、`/memories`、`/search` 入口调 `sanitize_input`，不安全则 400。
- **修 U5 误杀**：`SENSITIVE_WORDS` 只保留真正危险的（去掉裸 "key"/"token"，改为更精确的模式或仅用于日志脱敏）。`mask_sensitive_data` 用于**日志**脱敏（记日志前脱敏 email/phone/id），而非拦截用户输入。
- 长度限制 10000 保留。

### 3.4 上传约束（U6）
- KB 上传校验：扩展名白名单（pdf/docx/txt/md）+ 大小上限（`settings.MAX_UPLOAD_MB`，默认 20MB）。超限/非法类型 400。
